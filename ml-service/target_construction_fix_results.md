# Target Construction Fix — Attempt Report (Recommendation #1 not applied)

**Status: Recommendation #1 was attempted, found to be non-implementable as
literally specified, and reverted. No pipeline files were changed. Nothing
was retrained.**

## What was attempted

Per `target_construction_audit.md`'s Recommendation #1, `harmonize_sri_lankan_survey()`
was modified to normalize Sri Lankan's `harmonized_risk_norm` against the
min/max of the **pooled non-Sri-Lankan `harmonized_risk_norm` values**
(computed once, before Sri Lankan rows are processed), instead of Sri
Lankan's own 314-row min/max, while leaving the raw field
(`exhaustion_composite`, not `burnout_score`) and threshold-fitting (still
non-Sri-Lankan-only) unchanged.

## Why it was reverted

The pooled non-Sri-Lankan `harmonized_risk_norm` range turned out to be
**trivially [0.0000, 1.0000]** regardless of which sources are pooled. This
is a direct consequence of the existing, unchanged design: each of the four
non-Sri-Lankan `harmonize_*` functions already calls
`minmax_norm(df["burnout_score"])` **per source, before concatenation**
(`harmonize_datasets.py` lines 124, 144, 163, ~180) — so every source's own
`harmonized_risk_norm` column is independently rescaled so its own minimum
value becomes exactly 0 and its own maximum becomes exactly 1. Pooling four
columns that are each already forced onto [0,1] can only ever produce a
pooled range of [0,1] again; it carries no information about where any
source's *raw* `burnout_score` scale actually sits, which is what an anchor
step needs to be meaningful.

Applying that trivial [0,1] anchor to Sri Lankan's `burnout_measurement` (the
six-item exhaustion mean, a raw ~1–5 Likert average, observed mean ≈3.22)
produced a degenerate result: **every one of the 314 Sri Lankan rows'
`harmonized_risk_norm` collapsed to exactly 1.0** (verified: mean 1.0, std 0,
min 1.0, max 1.0 — full output below), because dividing by a denominator of
1 instead of 5 pushed nearly every value past 1.0, where it was clipped.
Downstream, this would have made **100% of Sri Lankan respondents
"Critical"** — a worse and more misleading result than the original
57.3%-Critical distribution being fixed, not an improvement.

```
Sri Lankan harmonized_risk_norm after the attempted fix:
count    314.0
mean       1.0
std        0.0
min        1.0
25%        1.0
50%        1.0
75%        1.0
max        1.0
```

This was presented to the user as a blocking finding before any retraining,
per the standing instruction to stop and report rather than work around
problems silently. The user chose to **revert the change and stop here**
rather than pick one of the two proposed alternative anchor implementations
(anchoring to the Likert instrument's theoretical 1-5 range, or anchoring to
a pooled *raw* pre-normalization `burnout_score` range across sources with
genuinely different native scales).

## Item 6 — does the raw-field mismatch still exist?

**Yes — unchanged, as expected.** This fix attempt only ever targeted
normalization *anchoring* (the min/max used inside `minmax_norm`), not the
underlying raw field. Non-Sri-Lankan sources still derive their target from
each dataset's native `burnout_score`; Sri Lankan still derives it from the
locally-defined six-item `exhaustion_composite` (the survey has no
`burnout_score` field at all). That mismatch was explicitly out of scope for
this task and remains exactly as documented in `target_construction_audit.md`
sections 1–3.

## Recommendation going forward

Recommendation #1 as worded in `target_construction_audit.md` ("anchor to the
pooled non-Sri-Lankan `harmonized_risk_norm` range") should be corrected —
that range is not a meaningful anchor given the existing per-source
`minmax_norm` design. If normalization-anchoring is still worth pursuing, the
two live alternatives are the ones proposed during this task:

1. Anchor Sri Lankan's `exhaustion_composite` to the survey instrument's own
   theoretical Likert bounds (1 and 5), i.e.
   `(burnout_measurement - 1) / (5 - 1)`, clipped to [0,1]. Population-
   independent, avoids the degenerate collapse, and is a standard choice for
   bounded Likert-scale composites.
2. Anchor to a pooled *raw* `burnout_score` range computed **before** each
   source's own `minmax_norm()` call — dimensionally weaker, since the four
   sources' raw `burnout_score` scales are not naturally comparable to each
   other either (which is why per-source normalization exists in the first
   place), so this is not clearly better than option 1.

Neither has been implemented; this file documents the attempt and revert only.
